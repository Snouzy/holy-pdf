# Desktop: Tauri shell on the site's code

_Written on 5 October 2026. Status: proof delivered in `apps/desktop`, then the built site loaded in the shell the same day (step 1); the desktop features come next._

## Context

On 4 October 2026, the Mac app in Swift is frozen: with two engines (PDFKit on Mac, PDFium and qpdf in WebAssembly on the site), every feature had to be built twice. The desktop app will be built with Tauri 2 on the site's code, for Mac and Windows first, Linux next. Before writing the app, one question had to be settled: does the site's engine run in the system webview, with its workers and its WebAssembly files, served by Tauri's protocol?

## What the proof establishes

`apps/desktop/smoke/` is a page built by Vite 8 (the version the site uses) from the site's sources (`apps/web/src/engine/client.ts` and its worker, imported by relative path, with no copy), with types checked by `tsc`. The Tauri shell loads it under the app's target CSP (`script-src 'self' 'wasm-unsafe-eval'; worker-src 'self' blob:`). The page runs five operations in a row and sends its JSON report to Rust through `invoke("smoke_report")`. Rust deserializes it and exits with 0 only if the five steps are present and passed; 1 otherwise; 2 if nothing arrives in 120 s. Since step 1, this page loads only if the binary starts with `--smoke` (the `smoke:engine` script, which compiles it with `tauri.smoke.conf.json`); the ordinary app does not know this page.

| Step | What it checks | Result (macOS 26.4.1, 5 October 2026) |
|---|---|---|
| Open a two-page PDF with PDFium | the two sizes, 200×100 and 100×200 | correct |
| Render a page as JPEG | a non-empty blob | 909 bytes |
| Repair with qpdf | two pages after the rewrite | correct (this step has a PDFium fallback: it does not prove qpdf alone) |
| Compress | goes through the qpdf worker nested in the engine worker, with no fallback | 510 bytes |
| Rotate the first page through `export`, reopen the copy | the first page measures 100×200 after rotation | correct, 671 bytes |

All five pass in 338 ms on the compiled binary, where `tauri://localhost` serves the page (the protocol of distributed apps), and in 118 ms under `tauri dev`, where a local HTTP server serves it. The webview is WKWebView. So: module workers, nested workers, the loading of the two `.wasm` files and the `ArrayBuffer` transfer work in both modes. The target CSP is checked on the binary only, because under `tauri dev` the page comes from the HTTP server of the CLI. The failure path is shown too: a four-step page under a verdict that expects five returned code 1, through `tauri dev --no-watch` as through the binary.

## Decisions

| Topic | Decision | Reason |
|---|---|---|
| Shell | Tauri 2, `apps/desktop`, identifier `com.snouzylabs.holypdf` | About ten MB, system webview, one codebase for Mac, Windows and Linux; see the [roadmap](../product/roadmap.md) |
| Shared code | Imported from `apps/web/src` by relative path, as long as there is no separate `engine` package | The pnpm workspace resolves the dependencies from `apps/web`; a shared package will come with Turborepo, after the `Packages/` vs `packages/` case question is settled |
| Proof | A test page, not the app, loaded from `dist-smoke` | It isolates the engine question from the interface question, and runs again with one command: `pnpm --filter @holy-pdf/desktop smoke` |
| Verdict | A Rust command deserializes the report and exits through `app.exit` with 0 only if the five expected steps passed | WKWebView has no WebDriver on Mac: the exit code is the only channel a script can read; counting the steps prevents a partial report from passing |
| Safeguards | The page gives itself 90 s, then returns a negative verdict; Rust exits with 2 after 120 s with no report | A worker that does not start throws nothing on the page side, and a page that does not load never calls Rust |
| Icons | Generated by `tauri icon` from `apps/web/public/favicon.svg` rendered as PNG | The halo is the logo; Tauri's default icons must not appear in the repository |
| Binary name | `HolyPDF` (`[[bin]]` in `Cargo.toml`); the package stays `holy-pdf` | Without a bundle, under `tauri dev`, macOS names the app in the Dock and in the menu bar after the executable file: neither the `CFBundleName` that Tauri embeds nor `setProcessName` counts (checked with `lsappinfo`, 5 October). Cargo refuses the space; the built app is named "Holy PDF" (`productName`) |
| Tools | Rust through rustup; Tauri CLI, Vite and TypeScript pinned as dependencies of the package | `tauri dev` calls `cargo` through the PATH: `~/.cargo/bin` must be in it (rustup adds it by default); on the JS side, `pnpm install` at the root is enough |

## Step 1: the site in the shell (5 October 2026)

> Superseded the same evening: the shell now loads a dedicated entry composed with the site's building blocks, and `--smoke app` replaces the page-by-page probe ([app shell spec](2026-10-05-desktop-shell-design.md)). What follows stays true for the CSP, the drop and the harness; it is no longer true for `frontendDist`, `devUrl` and the page list.

`frontendDist` points to `apps/web/dist`, which `beforeBuildCommand` rebuilds (`pnpm --filter @holy-pdf/web build`, 2.7 s). `pnpm desktop:dev` opens the site's development server (`devUrl`, port 4321), which must already run. There is no `beforeDevCommand`, because a second `astro dev` in the same folder would share the Vite cache of the first one and break it. `pnpm desktop:build` produces the app; the debug binary weighs 59 MB, with all of `dist` embedded.

Rust builds the window (`WebviewWindowBuilder`), not `tauri.conf.json`: `dist` has no `index.html` at the root (Cloudflare sends `/` to `/en`), so the shell opens `fr` when the system language starts with `fr`, and `en` otherwise (`sys-locale` crate). The macOS menus (Edit, Window, Quit) are the ones Tauri adds by default.

**CSP.** Tauri allows the inline scripts of a page by hashing the scripts of that page only into its policy. But the home page and the tool pages use Astro's `ClientRouter`: the next page arrives without a reload, and its scripts, unknown to the policy of the first page, would be refused. Also, the style hashes that Tauri adds make `'unsafe-inline'` void, which would block the site's `style=` attributes (436 on the home page). So `build.rs` computes the SHA-256 hashes of all the inline scripts of `dist` (7 distinct ones for 87 pages; JSON-LD excluded), writes the whole policy into `TAURI_CONFIG` for the codegen, and sets `dangerousDisableAssetCspModification`. The policy is the same for all pages: `script-src 'self' 'wasm-unsafe-eval'` plus these hashes, `style-src 'self' 'unsafe-inline'`, `connect-src 'self' ipc: http://ipc.localhost` for Tauri's call protocol (without it, each `invoke` goes through its `postMessage` fallback, after a violation), `object-src 'none'` and `base-uri 'none'`. Tauri sends this policy only with HTML documents: the workers run without a policy, and the Scanner worker relies on that (`new Function` in `scanWorker.ts`).

**Smoke test.** The binary accepts `--smoke`. Alone, it loads the engine test page. Followed by paths (`--smoke fr fr/compresser-pdf fr/faq en`), it loads the site with a probe injected before each page (`smoke/probe.js`). The probe records the CSP violations, the script errors and the load errors, then goes to the next page through a link of the page when one exists (Astro's router then makes the change, under the policy of the first page), or through `location.assign`. It removes `document.startViewTransition` before the page scripts: behind other windows the document is hidden, WebKit then skips the view transition, and the router leaves a rejected promise (seen on the first run). Without the API, the router makes the same DOM replacement and runs the same scripts, and the test no longer depends on where the window is on the desktop. Each report says by which path the page arrived (`via`, `load` or `swap`) and carries its title: Tauri serves a missing page as an error text, which loads with no error and no title. Rust checks the order of the pages and their titles. It exits with 0 after the last clean page, 1 at the first error, 2 if the chain did not finish in 120 s, 3 if the window is closed or the app quits (⌘Q) before the verdict, because these two endings would return 0, the code of an ordinary exit. Without `--smoke`, the shell registers neither the smoke test commands, nor the watchdog, nor the probe.

| Check | Result (macOS 26.4.1, 5 October 2026) |
|---|---|
| Engine page, five steps, under the generated CSP | 5/5 in 357 ms on `tauri://localhost` |
| `fr` home page, then Compress through the home page link, then FAQ, then `en` home page | 4 pages with no violation and no error, Compress arrived through the router (`via: swap`), four runs in a row; the whole `pnpm desktop:smoke` chain takes 38 s |
| Failure paths | missing page (`--smoke fr/nope`): 1; silent probe: 2; window closed or Quit from the menu: 3 |

## What comes next

The form of the app (a dedicated entry composed with the site's building blocks, instead of the whole site) is decided in [Desktop: the app shell](2026-10-05-desktop-shell-design.md), which takes points 1 to 3 below into its milestones. In order, each with its line here:

1. Save a result: the site does it through an `<a download>` link, which wry cancels on Mac as long as the shell has no `on_download` handler; so today no tool can save its copy in the shell. Add this handler with the native dialog. External links (GitHub, stores, legal notice): they replace the site in the window, with no way back; open them in the browser (`on_navigation` and `tauri-plugin-opener`). "View" on the result goes through `window.open`, which WKWebView ignores: open the file with the system viewer.
2. Open a PDF by double-click (file association), drop from Finder or Explorer, save in place through the native dialog, process a whole folder.
3. Diet: `dist` is 63 MB, including the home page videos (9.5 MB), OpenCV (13 MB), three Tesseract cores and PDFium twice; embed only what the desktop app serves.
4. Automatic updates, Mac and Windows signing, direct sales; stores after that.
5. Windows: the `smoke:*` scripts name the Unix binary (`src-tauri/target/debug/HolyPDF`); adapt them. Linux when WebKitGTK has run these same checks.
